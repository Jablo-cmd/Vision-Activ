# Vision Activ — Product Requirements

**Status:** Authoritative draft  
**Version:** 1.0-draft  
**Date:** 3 October 2026

## Product objective
Transform Vision Activ into the digital operating system for the Vision Activ transformation model. It must make the desired way of working visible, repeatable, measurable and improvable without creating bureaucracy.

## Primary users
- Employee / Practitioner
- Functional Head / Manager
- CEO / Executive
- Administrator

## Core domains
1. Transformation Passport
2. Planning & Execution
3. 12 Operating Protocols
4. Weekly Performance Pulse
5. Monthly Performance & Growth Review
6. RAG and Early Warning
7. Corrective Action
8. Evidence & Verification
9. Capability & Skills
10. Transformation Academy
11. Leadership Progression
12. Governance
13. Continuous Improvement
14. Recognition
15. Reporting

## Critical relationships
Plan → Deliver → Evidence → Review → Assess → Gap → Develop → Learn → Apply → Demonstrate → Improve.

A protocol gap may inform a PICC. A capability gap may create development work. Development may link to Academy learning. Applied learning produces evidence. Demonstrated capability updates the Passport. Delivery variance can create early warning and corrective action. Completed work can be evaluated for actual improvement.

## Success measures
- On-time delivery
- Accepted results without avoidable rework
- Predictability
- Recurring errors
- Support dependency
- Independence
- Client feedback
- Capability reassessment
- Protocol improvement
- Learning application
- Leadership progression
- Reduction in CEO dependency
- Organisational maturity

Completion counts alone are insufficient.

## Current scope
Single organisation; internal Vision Activ operating model; 12 protocols; planning/execution; performance/growth; capability/Academy; governance; evidence/assurance; reporting; notifications; security and POPIA foundations.

Future client-specific configuration, matrix teams, 360-degree feedback and moderation/calibration are outside current scope unless separately approved.

## Definition of done
A feature is done only when the data model, database authorisation, service/API behaviour, complete UI state transitions, error/empty states, audit/evidence requirements, relevant tests, documentation and traceability are complete and build/lint/typecheck/relevant tests pass.
